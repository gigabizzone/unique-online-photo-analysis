# CLAUDE.md

Guidance for working in this repository.

## What this is

An internal admin web app for **Aura Photo Science**, an Indian (bilingual English/Hindi)
aura-photo-analysis business. (The git repo / npm package is still named
`unique-online-photo-analysis`, but the user-facing app name was rebranded to "Aura Photo Science".) A single admin (Mukesh) logs in,
enters analysis scores for a customer across one of **six analysis types**, and the app generates
a branded PDF report (with QR code), stores it, and delivers it to the customer by **email** and/or
**WhatsApp**. Customers view their report at a public URL. There is no customer login — only the
admin authenticates.

The six analysis types: **Chakra** (7 chakras), **Planets** (9 planets), **Elements** (7 elements),
**Life Challenges** (dynamic 1–12 rows), **Overall** (3 fixed rows), **Wearables / Money Energy**
(dynamic items with dual +/- sliders + 5 remarks).

## Tech stack

- **Next.js 14** (App Router, `output: 'standalone'` for Hostinger), React 18, TypeScript (strict)
- **Prisma 6** + **PostgreSQL on Supabase** (pooled `DATABASE_URL` :6543 + `DIRECT_URL` :5432 for migrations)
- **NextAuth v4** — Credentials provider only (bcrypt cost 12, 5-attempt → 15-min lockout, JWT 7-day)
- **Supabase Storage** — `reports` bucket (public, PDF-only) via `SUPABASE_SECRET_KEY` (server only)
- **@react-pdf/renderer** — server-side PDF generation; **Noto Sans Devanagari** for Hindi
- **Nodemailer** over **Hostinger SMTP** — dual email (customer + admin acknowledgement)
- **qrcode** — QR encodes the public report URL into each PDF
- **Tailwind + shadcn/ui** (Radix), **React Hook Form + Zod** (schemas shared client+server), **Lucide** icons

## Commands

```bash
npm run dev               # next dev on :3000
npm run build             # prisma generate && next build
npm run seed              # seed admin (dotenv -e .env.local)
npm run db:migrate        # prisma migrate dev (uses DIRECT_URL)
npm run db:migrate:deploy # prisma migrate deploy (prod)
npm run db:studio         # prisma studio
npm run lint
```

Env lives in `.env.local` (see `.env.example`). Note: **`.env.local` points at the live Supabase
production database** — there is no separate dev DB. Be careful with destructive scripts.

## Architecture & conventions

**Layout of `src/`:**
- `app/(auth)/login` — login page; `app/(dashboard)/*` — protected admin pages; `app/report/[publicId]` — **public** report viewer
- `app/api/**` — route handlers (analysis create, report generate/pdf/email, history, customers, settings, auth)
- `lib/` — server utilities: `db.ts` (Prisma singleton), `auth.ts`, `mailer.ts`, `supabase-storage.ts`,
  `branding.ts`, `publicId.ts`, `qr.ts`, `whatsapp-link.ts`, `pdf-fonts.ts`, `score-color.ts`, `utils.ts`
- `lib/schemas/` — Zod schemas per analysis type + `profile.ts` (shared by RHF and API validation)
- `constants/` — `branding.ts` (BRAND, SOCIAL_LINKS, ANALYSIS_TYPES) + per-type metadata (`chakras.ts`, etc.)
- `components/` — `forms/`, `reports/` (+ `reports/public/`), `ui/` (shadcn), layout pieces
- `middleware.ts` — auth gate; **exempts `/report/*` and `/api/report/*`** so public links / QR work

**Key patterns:**
- **publicId** format: `APS-{YYYY}-{PREFIX3}-{SEQ5}` (e.g. `APS-2026-CHK-00001`). Generated by
  `generatePublicId()` via an atomic `Counter` upsert keyed `${PREFIX}-${year}` — collision-safe under
  concurrency. Prefixes: CHK, PLN, ELM, LCH, OVR, WRB.
- **Customer upsert key is `email`** (unique). Analysis creation runs as one Prisma transaction:
  upsert customer → bump counter/publicId → insert `AnalysisEntry`.
- `AnalysisEntry.data` is enriched JSON (rows + label/sanskrit/color metadata) so PDF & public view
  render without re-resolving constants. Audit timestamps: `emailSentAt`, `adminAckSentAt`,
  `whatsappOpenedAt`, `pdfDownloadedAt`.
- **Branding** is a single-row `Settings` table (id `"main"`), read via `getBranding()` (in-memory
  cached; `clearBrandingCache()` on PUT), falling back to `constants/branding.ts` defaults.
- The four **scored-rows** types (Chakra/Planets/Elements/Overall) share `ScoreRowsAnalysisFlow`
  (form) and `ScoreRowsReport`/`ScoreRowsPublicView`. Life Challenges & Wearables have bespoke flows.
- Score range is **-50..+50** everywhere; color maps red→neutral→green via `lib/score-color.ts`.
- **Hindi fonts ship from `public/fonts/`** (not node_modules) because Hostinger drops
  `node_modules/@fontsource` files at runtime — registered in `lib/pdf-fonts.ts`.
- WhatsApp uses **`wa.me` deep links** (no Business API) — admin sends manually from their device.
- API convention: session check → JSON parse → Zod `safeParse` → DB → JSON. Email-send and
  storage-cleanup failures are non-fatal.

## Scripts (`scripts/*.mjs`, all use `dotenv -e .env.local`)

Diagnostics (read-only): `check-smtp`, `check-supabase-secret`, `check-email-stamps`,
`find-latest-entry`, `inspect-chakra-data`, `verify-prisma`. Maintenance: `cleanup-orphan-storage`
(orphan PDFs), `reset-admin-lockout`. **Destructive:** `cleanup-smoke-test-data` (deletes @example.com
data), `wipe-all-test-data` (clears everything — dry-run unless `--yes`).
